# ПЛАН: Расчёт цены радиатора по секциям (при ненахождении точного количества)

**Ветка:** `feat/search-mode`
**Дата:** 2026-08-27
**Проблема:** Позиции 36-41 (МС-140, разное количество секций). На santech.ru
существуют только варианты 4 и 7 секций. Варианты 2, 3, 5, 6 секций отсутствуют
в природе. Агент сохранял цену 4-секционного как аналог — это неверно.

**Статус:** АНАЛИЗ ИДЕИ (реализация после утверждения)

---

## 1. Идея пользователя

Создать инструмент/инструкцию для LLM-агента:
- **ТОЛЬКО для радиаторов** (секционных чугунных/стальных/биметаллических)
- Если точное количество секций не найдено на сайте
- Рассчитать цену одной секции из известного варианта
- Умножить на нужное количество секций
- Проставить рассчитанную цену
- Пометить строку «рассчитано программно»

## 2. Объективный анализ

### 2.1. Экономическая обоснованность

Ценообразование секционных радиаторов — **линейное**: каждая секция добавляет
фиксированную стоимость к цене изделия. Проверка на реальных данных:

| Вариант | Секций | Цена santech | Цена за секцию |
|---|---|---|---|
| v3 | 4 | 5 636,80 ₽ | **1 409,20 ₽** |
| v5 | 7 | 9 865,80 ₽ | **1 409,40 ₽** |

Расхождение: 0.20 ₽ на 7 секций (0.014%) — погрешность округления. **Цена за секцию
стабильна.** Это подтверждает: расчёт по секциям корректен.

### 2.2. Применимость ТОЛЬКО к радиаторам

**Почему только радиаторы:**
- Секционные радиаторы (чугунные МС-140, стальные панельные, биметаллические)
  продаются по принципу «цена × количество секций»
- Другие товары (краны, трубы, клапаны) НЕ имеют линейной зависимости цены от
  размера/длины — там своя ценовая сетка

**Как определить «радиатор»:**
- По `product_type` = `plumbing_heating_radiators`
- И по наличию суффикса `-0,9-N` (количество секций) в spec_text
- Или по наличию слова «секционный» / «радиатор» + цифра секций в тексте

### 2.3. Риски и митигация

| Риск | Митигация |
|---|---|
| Разные материалы (чугун vs сталь) | Проверять МОДЕЛЬ (`model_designators`): МС-140 ≠ Panel Compact |
| Разная высота/межосевое расстояние | Модельный код включает высоту (МС-140 Мх500 — высота 500 мм) |
| Скидка за объём на большем количестве | Расхождение 0.2 ₽ на 7 секций — несущественно |
| LLM ошибётся в расчёте | Расчёт делать в КОДЕ, не LLM |

### 2.4. Техническая реализация (два варианта)

**Вариант A (расчёт в коде, надёжно):**
- Модуль `src/radiator_calculator.py` (Qt-free, тестируемо)
- Вызывается из `process_row`, когда все сайты проверены, а точного количества
  секций нет
- Находит в confirmed_prices запись с той же МОДЕЛЬЮ, но другим количеством секций
- Извлекает `-0,9-N` из spec_text, рассчитывает цену за секцию
- Сохраняет новую цену с `confidence=0.70` и `reason="рассчитано программно"`
- `requires_review=True`

**Вариант B (правило в промпт + код-хелпер):**
- LLM получает правило: «для радиаторов: если точного количества секций нет,
  рассчитай цену из известного варианта и сохрани с confirm=true»
- Код-хелпер `_calc_radiator_price(spec_text, known_prices)` — подсказка LLM
- LLM решает, код считает

Рекомендую **Вариант A**: расчёт в коде (не зависит от LLM), тестируем, надёжен.

## 3. Что нужно для реализации

### 3.1. Новый модуль: `src/radiator_section_pricer.py`

```python
_SECTION_RE = re.compile(r"-0,9-(\d+)", re.IGNORECASE)

def extract_sections(spec_text: str) -> int | None:
    """Извлекает количество секций из spec_text: «МС-140 Мх500-0,9-4» → 4."""
    m = _SECTION_RE.search(spec_text or "")
    return int(m.group(1)) if m else None

def calculate_price(price_per_section: float, target_sections: int) -> float:
    """Цена = цена_секции × количество_секций."""
    return round(price_per_section * target_sections, 2)

def find_base_price(memory_manager, spec_text: str) -> tuple[float, int, str] | None:
```

0.014%). Реализация в коде (Вариант A) безопасна, тестируема, не зависит от LLM,
работает ТОЛЬКО для радиаторов с явным суффиксом `-0,9-N`.
