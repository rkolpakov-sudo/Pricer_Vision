# План: сокращение времени на позицию без потери качества поиска

Дата: 2026-08-28
Основание: анализ двух прогонов (предпоследний — `Desktop/runtime.log`, 99 строк с
браузером, ~10 ч; текущий — сессия `06acea47`, ~10.6 мин/строка). Детали дефектов и
фактура — в анализе сессии (переписка), здесь — план реализации.

## Принцип

1. **Механические фиксы** — код, не влияющий на решения LLM: контекст, кэш, размеры
   результатов. Память (RowFacts) переживает изменения → качество не может упасть.
2. **Система-советник** — как уже сделано для `content_only_rounds`/`_model_mismatch_hint`:
   система НЕ решает, а возвращает tool-сообщение с аргументами; право действовать — за LLM.
3. Запрещено: жёсткие лимиты поиска, подмена запроса скриптом, ослабление реюза/строгих
   размеров/`model_designators`. Модель LLM не меняется.

## Фактура (коротко)

- 50% вводов запросов (109/218) — точные дубликаты с полной церемонией поиска.
- 9 «монстр»-запросов (весь spec_text, с `;`) — заведомо провальные.
- 248/941 `browser_evaluate` — повтор того же JS (кэш ловит лишь 25).
- 54 блокировки ухода при найденной цене (`navblock`) — агент не сохраняет кандидата.
- `context_trim` не удерживает бюджет: `kept N of N` — хвост от последнего user-сообщения
  сохраняется целиком, контекст растёт до 14–17k токенов → каждый вызов LLM 20–100 с.
- Фантомные поиски: «очистка поля + чтение body» без `browser_type` (позиции 53, 80, 90...).
- Деградация запроса с потерей размера/типа/Ду (26 случаев).

## Фаза A. Механические фиксы (0 риск)

### A1. `_trim_messages_for_budget` (`agent_loop.py`) — реальный лимит контекста
Проблема: алгоритм сохраняет «хвост» от последнего user-сообщения целиком; в реальном
диалоге последний user = спека (индекс 1) → tail = вся история → трим не работает,
контекст растёт до 14–17k.

Решение:
- Оставить system.
- Сохранять **первое user-сообщение** (задача: спека+контекст) как якорь; не давать ему
  монополизировать бюджет (cap = budget//3, при превышении — усечь контент).
- Сохранять **новейшие полные обмены** (`assistant(tool_calls)` + его `tool`-результаты),
  не разрывая пары `tool_call_id ↔ tool` (новая чистая функция `_keep_newest_exchanges`).
- Середина отбрасывается (свежий слайдинг-окно вместо «старое+хвост»).

Эффект: каждый вызов LLM ≈ 8k токенов вместо 14–17k → латентность вызова падает
пропорционально. Память строки не теряется: RowFacts пересоздаётся per-call и
инжектится после трима.

Тесты: существующие `tests/test_context_optimizer.py` должны остаться зелёными;
добавить: хвост-превышающий-бюджет, сохранение пары assistant+tool, якорь-задачи при
наличии позднего user-сообщения.

### A2. Усечение крупных результатов `browser_evaluate` в сообщении
Проблема: однострочные JSON-результаты (до 6715 символов) проходят полностью
(лимит 200 строк не работает для одной строки).

Решение: `content_to_send` для `browser_evaluate` усекать до `EVALUATE_MESSAGE_CAP=6000`
с пометкой «…(результат усечён)». Логика цены (`_extract_price_candidate`) работает на
полном `tool_content` ДО усечения; `price_hint` подставляется в начало → LLM не теряет цену.

### A3. Нормализация JS-хэша в `eval_cache`
Проблема: кэш `(домен, md5(js))` — точное совпадение; 223 «почти одинаковых» JS
(пробелы/кавычки) не попадают в кэш.

Решение: хэшировать `_normalize_js(js)` (схлопнуть пробелы/переносы, унифицировать
кавычки `'`/`"`). Использовать в обеих точках (чтение `:807`, запись `:841`).

## Фаза B. Система-советник (решает LLM, видит риски)

Все — в точках перехвата инструментов `process_row` (ветки browser_type/browser_navigate).

### B1. Дубли запросов — пропуск с советом (`browser_type`)
- `RowFacts.seen_query(domain, query)` — число прошлых вхождений того же текста.
- Если тот же запрос уже вводился на этом домене:
  - 1-й повтор: tool-сообщение «запрос "X" уже вводился на этом сайте и результата не дал.
    Измени текст или переключись на другой сайт/сохрани аналог»; **`continue`** (не исполняем).
  - 2-й повтор: жёстче, аналогично `CONTENT_ONLY_FORCE`.
- Проверка ДО автоклира поля (`_clear_field_js`), чтобы не оставлять очищенное поле.

### B2. «Монстр»-запрос — пропуск с советом (`browser_type`)
- Если текст запроса содержит `;` (сигнатура вставки всего spec_text) — tool-сообщение
  «запрос слишком длинный для поиска магазина; используй артикул/модель/размер
  (ключевые токены в контексте)»; **`continue`**.
- Если >70 символов без `;` — только подсказка в результат (не пропуск): возможно
  легитимный длинный запрос.

### B3. Деградация запроса (потеря модели/размера) — подсказка
- В `browser_type`: сравнить `model_designators(prev_q)` и `_size_key(prev_q)` с новым
  запросом; если новая формулировка потеряла модель/размер — подсказка «новый запрос
  потерял [модель/размер]; упрощай, сохраняя размер/тип/Ду, либо смени сайт».
- Не пропускать (упрощение иногда корректно) — только подсказка.

### B4. Фантомные поиски (evals без ввода) — факт
- `RowFacts.record_browser_call` считает `evals_since_type` (растёт на evaluate,
  сбрасывается на `record_query`).
- `to_prompt_block`: при `evals_since_type >= 4` — строка «запрос поиска не вводился уже
  N извлечений подряд — только browser_evaluate; для реального поиска используй browser_type».
- Информационно, без пропуска.

### B5. Сохранение найденной цены после navblock
- `RowFacts.record_price_candidate(hint)` — хранить подсказку цены; `record_navblock()`,
  `navblocks` счётчик.
- В гейте «Navigate blocked» (`:750`): сообщение дополнить значением цены-кандидата и
  URL; при 2-й блокировке — жёстче («сохрани цену через save_confirmed_price СЕЙЧАС,
  затем переходи»).

### B6. Повторная навигация на тот же URL — подсказка
- `RowFacts.record_url(url)` / `seen_url(url)`.
- В `browser_navigate`, если URL уже открывался в строке — подсказка «страница уже
  открывалась; работай с текущей или укажи новый URL». Не пропускать (refresh допустим).

### B7. Лимит сайтов без результата — guidance
- `RowFacts.distinct_sites()` — число посещённых доменов.
- При навигации на новый домен: если посещено >=3 сайтов и `not price_candidate_seen`
  и `not price_confirmed` — user-сообщение «уже N сайтов без результата; либо сохрани
  лучший аналог (сниженный conf), либо заверши строку».
